# Luma console design

The console follows Cloudflare's current dashboard and its public design system, Kumo. Reviewed against Kumo's `theme-kumo.css` tokens, `LayerCard`, `ResourceListPage`, `Sidebar`, `Table`, `Badge`, `Button` and Flow sources on 2026-10-31. These rules apply to every workspace: applications, deployments, observability, infrastructure and settings.

## Sources and component decision

- [Kumo](https://github.com/cloudflare/kumo) is Cloudflare's public React component library, built on Base UI. Its [resource-list layout](https://github.com/cloudflare/kumo/blob/main/packages/kumo/src/blocks/resource-list/resource-list.tsx) constrains page width and standardizes title, description and resource content.
- [Flow](https://kumo-ui.com/components/flow/) draws directed relationships as cards on a dotted canvas. Luma keeps Cytoscape and Dagre for graph interaction and matches Flow's look through styles.
- Kumo ships [Phosphor](https://phosphoricons.com/) icons. Luma vendors the glyphs it uses into `dashboard-src/src/components/icons.ts`, generated by `scripts/generate-dashboard-icons.mjs` from `@phosphor-icons/core` (MIT). Add an icon by mapping a name in that script and rerunning it; `check-luma.sh` runs it with `--check`.
- [cf-ui](https://github.com/cloudflare/cf-ui) was archived in 2021 and is not a suitable new dependency.

Retain Luma's existing React 19, Base UI, Tailwind 4 and shadcn components. Adopt the reference's visual rules through shared semantic tokens and components; do not introduce a second component or graph framework just for appearance.

## Shared rules

- Surfaces, back to front: grey `--canvas` behind content; white chrome (`--background`) for the sidebar, top bar and controls; white `--card` layers with a hairline ring and `shadow-xs`; `--muted` for table header bands and code. `--border` separates layers and `--hairline` divides rows inside a layer.
- Status colours are indicators (`--success`, `--warning`, `--info`, `--destructive`: dots, meters, icons). Text on a status tint uses the matching `*-foreground` on `*-soft`. White text sits only on `--primary` and `--destructive-fill`. Every text pairing in both themes stays at 4.5:1 or better; check translucent fills by compositing them over the real background first.
- The sidebar holds identity (logo and cluster id), a "Search or jump to" trigger for the ⌘K command palette, grouped workspaces whose secondary pages expand inline, a fleet health line and the collapse control. The collapsed rail opens secondary pages in a flyout. The top bar holds breadcrumbs, sync status, a docs link and the account menu (appearance, language, sign-out). There is no global refresh button. Each destination keeps a single home in the navigation.
- Main content is at most 1400px wide with responsive gutters and a 24px section rhythm. Terminal workspaces keep their full available size.
- One page heading with actions aligned right; no icon or eyebrow in the title, because the sidebar and breadcrumb already name the workspace. Header metrics are a quiet line of labelled counts, not chips that look clickable. Application detail pages show the object name with line tabs below.
- List pages put search and filters in a toolbar row above the list, without form labels (each control keeps an accessible name). A list card that holds only a table drops its own title.
- Tables placed alone in a card run edge to edge: shaded header band, hairline row dividers, first and last cells aligned to the card gutter. Key/value tables use `TableHead scope="row"` for a fixed label column. Row actions are ghost buttons plus a kebab menu.
- Key figures use `StatTile`: small label, large value, muted context, an optional meter. CPU, memory and disk in tables use `UsageMeter`, which only takes a tone colour above 75% and 90%.
- Status badges come from `StatePill`/`stateVariant`. Healthy and unknown states use the quiet dot form so lists of running things stay calm; warnings and failures use a filled tint. A missing value shows as `—`.
- Primary buttons use Kumo's emphasis treatment (top-lit gradient that only darkens, inner highlight, darker ring). Secondary actions are white bordered buttons; destructive actions in rows are outlined red, and the final confirmation in a dialog is solid red.
- Page-level navigation tabs (application detail, storage, network) use the underlined `line` variant; view switches inside a card keep the segmented control.
- Dates, sizes and percentages go through `format.ts` (`formatDateTime`, binary-unit `formatBytes`, `formatPercent`). In-app links use `spaLink` so modified clicks still open a new tab.
- Network views separate routes from node topology. Route search and ingress type filter apply to both diagram and table. Graph nodes are white cards with hairline borders on the dotted `topology-grid` canvas; graph colours are composited to opaque values before they reach Cytoscape.
- Preserve light and dark themes, keyboard access and narrow-screen navigation. Avoid adding API diagnostics or unsupported health claims to fill empty states.

## Validation boundary

Use local development fixtures for layout and interaction checks. These checks do not establish production health or change any live route, certificate or deployment.

## Public website

The GitHub Pages site uses the same neutral surfaces, 8px cards, thin borders and blue actions. Its marketing layout has larger editorial headings while the embedded illustrative console stays compact. English and Chinese landing pages carry equivalent content. Product illustrations use example domains and explicit sample-data labels, never a production-health claim.

Documentation is built from repository Markdown into standalone pages with navigation, tables and a table of contents. See [Website maintenance](website.md) for the build and publishing workflow.
