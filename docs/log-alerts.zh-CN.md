# 服务日志告警 {#service-log-alerts}

在控制台的「可观测性 → 规则 → 服务日志匹配」选择一个应用（Nomad job ID），按需填写服务名、包含文本、排除文本或 JSON 字段和值。文本区分大小写，所有条件同时满足；JSON 字段支持点分路径。预览返回匹配条数和一个最多 512 UTF-8 字节的样例，不保存规则或发送通知。

阈值采用「大于」语义：填 4 表示至少匹配 5 行，填 0 表示一行即触发。建议匹配任务失败摘要，避免按堆栈行数重复统计。重试产生的摘要分别计数，并不代表不同业务任务。

Control 保存规则并读取小份缓存结果。独立的 `observe/log-alerts` 进程调用 VictoriaLogs 原生聚合接口，查询不在 Control 进程或 SQLite 锁内执行。告警事件、确认、静默、恢复和通知继续复用 Control 告警中心，不再通过 Alertmanager 重复发送。

## 资源限制与异常语义 {#budgets-and-failure-semantics}

- 最多 20 条日志规则，每条限定一个应用，窗口为 60–900 秒。
- 串行查询，全局查询间隔至少 2 秒，单条规则评估间隔至少 60 秒。VictoriaLogs 查询超时为 1 秒，客户端超时为 2 秒。
- 预览仅保留一个合并槽位，每 10 秒最多接受一个新预览，与定时规则共享查询预算。页面轮询最多 50 秒。
- 聚合响应和配置交换上限均为 256 KiB，交换结果包含每条规则最多 16 个来源计数。Control 本机请求超时 500 毫秒，不等待日志查询完成。单条规则另有 2400 字节配置预算。
- 不创建日志临时文件、磁盘缓存、动态规则文件、持久化卷或后台重试任务。运行时根文件系统只读，禁用 Python 字节码写入，内存上限 96 MiB，CPU 调度份额 50 MHz；CPU 份额不是硬配额。
- 日志采集器必须追平所选服务的所有运行实例和日志流。读取或导出失败、轮转丢失、采集落后以及超过 150 秒的统计结果均视为不可用。监控状态最多保留 2048 个流。
- 指定 JSON 字段缺失、窗口内没有源日志，均不视为零错误或业务恢复。正常情况下长期无日志的服务应使用心跳或业务指标补充监控。
- 统计使用现有采集时间，重启、补采和重试可能影响窗口计数。错误减少不能证明丢失的业务任务已得到补偿。

## 部署和配置 {#delivery}

升级 Control（包含 API 和控制台），再部署 `observe/`，安装仅监听本机 9109 端口的日志告警进程及采集覆盖接口。旧版 observe 会返回不可用，不会伪造成功。文本规则无需修改业务应用。

部署本身不启用规则，需要在告警中心创建规则并选择通知渠道。编辑规则会保留 `logQuery`；匹配条件变化会重置当前事件，与阈值变更的处理一致。

`luma/log_alert_rules.py` 是共享规则契约，`observe/log_alert_rules.py` 保留完全相同的副本，保证 observe 构建目录独立，回归检查确保二者一致。

第一版仅接受声明式配置，不开放任意 LogsQL、无界正则、跨应用查询或历史回填。重要业务的完成率、耗时和积压监控，后续应结合业务指标实现。


## 事件日志与应用入口 {#incident-evidence-and-application-navigation}

每个应用详情页提供「告警」页签。告警中心的事件和规则列表也支持按应用筛选；统计和分页在数据库中按应用索引执行，不会先取一页再过滤。适用于全部应用的通用规则仍会显示，名称碰巧相同的节点告警不会混入应用事件。

同一次原生聚合使用 `json_values(...) limit 3` 取得最多 3 条代表性日志，并按实际来源汇总匹配计数。结构化任务样例另按执行身份批量关联异常详情，见下方口径。样例会清理常见凭据，消息最多保留 512 UTF-8 字节（开头和结尾），每条完整样例最多 900 个 JSON 编码字节。配置和结果交换上限为 256 KiB，串行查询频率及 96 MiB 进程内存上限保持不变。

每个事件只保存一份有上限的日志快照，仅在新采样仍超过阈值时替换；恢复后保留最近的异常窗口。列表只传摘要，详情先读取已保存的摘要、来源、采样时间、窗口和匹配条数；完整堆栈另按原执行身份查询保留日志。群消息使用同一份快照，并链接至对应应用的告警详情。「检索此窗口日志」会带上原应用、服务和时间范围，首次最多返回 100 行。

样例可能截断，顺序不保证，重复日志也可能合并；匹配行数不等于独立业务失败次数。快照随现有告警历史保留策略清理，不另建临时文件或不断追加的样例历史。升级前未保存日志的历史告警会明确提示，不会用当前日志冒充历史异常。


## 统一任务失败口径 {#task-failure-semantics}

SDK 任务规则使用 `logQuery.mode: task_failures`，固定匹配 `task.finished`：
业务结果 `failed` 或执行结果 `failed` 均为失败，业务失败不受框架成功影响。
同一 Trace/Span 的重复投递只计一次；阶段、异常详情和生产者投递记录不增加计数。
此模式不同时设置文本或 JSON 条件，仍可配置应用、服务、窗口、阈值和通知渠道。

应用失败比例和任务结果表使用同一套已保留的结束日志。失败优先；其余重试中、
取消和未知业务结果（包括 `needs_review`）单列。比例为失败 /（成功 + 失败）。
没有已判定的结束记录、查询失败或超过响应限制时显示未知，不补零。
这些数字是观测到的执行次数，不是独立订单数，也不保证日志完整；未上报 SDK
结束日志的旧任务显示未知。耗时、活跃数继续使用指标。后续成功重试保留此前失败。

告警在截断前保留 Trace/Span/任务 ID，并追加一次批量异常详情查询（服务端
1 秒、客户端 2 秒）。查询限定原应用、服务、分配和执行，窗口起点前扩 60 秒，
补充边界附近的详情；详情查询失败不影响告警触发。卡片保存脱敏异常摘要，
完整堆栈由详情页按同一执行读取原始保留日志；缺失、不可用和截断明确区分。
规则交换限定 256 KiB、每条样例仍限定 900 字节，不在 SQLite 保存全量日志。

状态页分别展示所选窗口中曾触发的应用告警和当前触发/等待数量。
告警恢复只说明阈值条件清除，不代表失败业务已补偿。

交付需同时更新 Control（含 Dashboard）及独立部署的 `log-alerts` 服务，再将
SDK 任务失败规则切到 `task_failures`，停用同一服务上重复的框架失败文本规则。
生产者投递失败和未接入 SDK 的旧任务规则保留独立范围。


使用预构建镜像的 Compose 部署可从已通过验证的不可变发布标签单独发布此进程：
`gh workflow run log-alerts-image.yml --ref v0.2.38`，产物为
`ghcr.io/liutianjie/luma-log-alerts:v0.2.38`。通过已有 Compose 工作流替换该镜像，
其余 Observe 镜像保持原引用。发布镜像本身不升级运行中的服务，也不修改规则。

## 按来源限时静默 {#expiring-source-silences}

告警详情提供「按来源限时静默」，可选择 1、6、24 小时；告警列表展示生效中的来源和截止时间，并支持提前解除。匹配范围为规则 ID、实际对象和来源标签：结构化任务日志优先使用 `attributes.task.name`，普通日志使用采集的服务 `task` 标签，指标告警使用规则限定的任务、服务或实际对象。Luma 读取观测字段，不登记业务任务、订单或业务错误码。

来源计数来自完整窗口的原生聚合，与最多 3 条展示样例分开。每条规则最多传递 16 个明确来源，标签保留精确值；无法识别、超过标签长度或来源数量上限的剩余匹配继续通知，不继承其他来源的静默。

静默只过滤通知匹配，原始观测值和事件恢复条件保持完整。静默 A 后，A、B 混合窗口中的 B 仍参与阈值判断；新的未静默来源会绕过其他来源的重复提醒间隔。到期或提前解除后，下一次新鲜评估恢复通知。静默跨同一规则与对象的事件生效；修改规则条件时清除对应静默。排队中的混合来源通知重新生成，恢复通知仍单独发送，与原告警使用相同事件编号。

### 飞书卡片按钮 {#feishu-source-actions}

在「通知 → 编辑渠道」启用来源静默按钮，填写飞书应用的 Verification Token 和 Encrypt Key；凭据保存后不回显。同一 App ID 的多个群渠道共用此配置。保存后，将页面展示的地址 `https://<Control 域名>/v1/alerting/feishu/callback/<App ID>` 填到飞书开发者后台「事件与回调 → 回调配置」，选择发送至开发者服务器并订阅 `card.action.trigger`，按飞书要求发布应用配置。

新告警和持续提醒卡片为最多 3 个明确来源提供时长按钮。点击后仅更新被点击卡片的静默状态和截止时间；告警与恢复各自发送新卡片，保留群消息中的恢复提醒。群成员可操作所在告警群卡片中的来源；回调验证应用、签名、时间戳、群聊及持久化卡片令牌，并对重复回调去重。回调地址验证不需要 Luma 登录，普通管理 API 仍使用原认证。

Control 与 `log-alerts` 必须配套升级才能提供日志来源按钮。旧聚合器没有完整来源计数时继续告警，界面不从样例文本猜测静默范围。回调凭据和飞书订阅配置完成后，新发送的卡片才具备可用操作；已发送的旧卡片可通过详情链接进入看板操作。
